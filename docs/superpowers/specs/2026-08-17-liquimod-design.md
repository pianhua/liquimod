# LiquiMod 设计文档

> 崩铁（架构预留多游戏）3Dmigoto Mod 管理器 · 重写 JASM
> 日期：2026-08-17 · 状态：待实现

## 1. 背景与目标

重写 [JASM](https://github.com/Moonholder/JASM)（C#/WinUI3，约 4.5 万行）。动机：

- **更稳定的语言/运行时**：Rust 核心，内存安全、无 GC 停顿
- **性能更好**：流式解压、毫秒级原子启停、编译时前端框架
- **管理逻辑更优**：Junction 部署模型取代 JASM 的"改名禁用"
- **UI 更美观**：iOS 26 液态玻璃（Liquid Glass）设计语言
- **沉浸式安装**：无弹窗解压；加密压缩包可靠触发内联密码输入（JASM 靠解析 7z.exe stdout 文本，数据加密型压缩包静默失败）

### MVP 范围（第一版）

- 角色/Mod 网格浏览、搜索
- 拖放安装（压缩包/文件夹，含嵌套、加密包）
- Mod 启用/禁用（Junction 部署）
- 游戏运行检测 + 自动 F10 刷新（提权 helper + 命名管道）
- 文件监控对账
- 预设（启用清单，一键应用）
- 密码本（增删改，安装时自动尝试）
- 明/暗双主题，跟随系统

### 明确不做（YAGNI）

- GameBanana 在线下载、完整的自动分类规则库、角色自定义编辑器、多开游戏、Mod 导出——后续迭代
  - 注：安装时的轻量探针推断（ini 引用/贴图结构提示角色，用户确认）**在范围内**；不做的是 JASM 那套完整规则库
- 非 NTFS 文件系统支持（用户环境已确认全 NTFS）

## 2. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 核心 | Rust + tokio | 内存安全、异步 IO、单文件分发 |
| 桌面壳 | Tauri 2 | 小包体、WebView2 渲染、原生 IPC |
| 前端 | Svelte 5 + TypeScript + Tailwind | 编译时框架无运行时开销；WebView2 完整支持 backdrop-filter |
| 解压 | sevenz-rust2 / zip / unrar（Rust 库） | 结构化错误（密码错误是错误类型而非 stdout 文本） |
| 存储 | SQLite（rusqlite） | 元数据/标签/预设/密码本/操作日志 |
| 文件监听 | notify crate | Mods 目录对账 |
| 日志 | tracing + 滚动文件 | UI 内可查看复制 |
| F10 输入 | windows crate SendInput | 提权 helper 内使用 |

## 3. 整体架构

```
Tauri 2 前端 (Svelte 5, 液态玻璃 UI, 明/暗跟随系统)
      │ Tauri IPC（命令 + 事件推送）
Rust 核心进程
  ├─ library/   Mod 仓库管理（文件 + SQLite 索引）
  ├─ deploy/    Junction 部署引擎（启停 = 创建/删除联接）
  ├─ archive/   压缩包安装（流式、嵌套递归、密码本自动尝试）
  ├─ watcher/   Mods/ 与 Library/ 监听对账（notify）
  ├─ games/     Game trait 抽象；HSR 首个实现（角色列表/图片/3Dmigoto 规则）
  └─ refresh/   命名管道客户端，通知 helper
      │ 命名管道（仅本机）
refresh-helper.exe（极简 Rust 程序，按需 UAC 提权，收 "1" 即向游戏窗口发 F10）
```

**真相原则**：磁盘文件是唯一真相，SQLite 只是索引。数据库损坏可从文件系统重建，永不丢 Mod。

**多游戏抽象**：`Game` trait 定义角色列表、图片资源、3Dmigoto 路径规则、进程检测。第一版只实现 HSR，trait 保证后续游戏是纯增量。

## 4. 核心机制

### 4.1 Junction 部署模型（替代改名模型）

- 所有 Mod 存于应用仓库：`Library/<角色>/<Mod名>/`
- **启用** = 在 3Dmigoto `Mods/` 下创建 NTFS 目录 Junction 指向仓库目录
- **禁用** = 删除 Junction
- Junction 创建无需管理员权限；启停是元数据级原子操作（毫秒）
- Mod 本体永不移动/改名：无路径失效、无文件锁冲突
- 预设 = 一组启用清单，应用预设 = 一次性全量对账重建 Junction（原子替换）

### 4.2 沉浸式安装流

```
拖入 → 角色卡片原位浮现"安装中"玻璃浮层（不弹窗）
     → 流式解压到临时区（进度环内嵌显示）
     → 探针扫描（ini 引用/贴图结构）推断角色，内嵌显示可改
     → 加密包：先静默尝试密码本；全部失败则卡片原位变密码输入框；
       成功后询问是否存入密码本
     → 嵌套压缩包自动递归，全程同一浮层
     → 复制进仓库 → 写 SQLite → 后台生成缩略图
     → 若角色设为"自动启用"→ 立即部署 Junction
     → 卡片平滑翻转为 Mod 卡片
```

### 4.3 启停 + 自动刷新

```
点击/空格 → deploy 引擎创建/删除 Junction（原子）
         → 更新 SQLite
         → 游戏运行中 → 命名管道通知 helper 发 F10
         → 事件推送前端，卡片状态动画
```

### 4.4 文件监控对账

watcher 监听 Mods/ 与 Library/。外部变动 → 自动对账 → 推送 UI。绝不静默改动用户文件，只对账与提示。

### 4.5 F10 提权 helper

独立小 exe（约百行 Rust）：UAC 提权启动 → 监听命名管道 → 收到 "1" 向游戏窗口 SendInput(F10)。不监听键盘、无网络。首次刷新时提权，之后驻留；应用退出时一并退出。

## 5. 数据模型（SQLite）

- `mods`：id、名称、角色、仓库相对路径、来源、安装时间、缩略图路径
- `mod_state`：启用状态（与文件系统对账后的缓存）
- `presets` / `preset_entries`：预设与启用清单
- `passwords`：密码本（可选 DPAPI 加密）
- `settings`：游戏路径、3Dmigoto 路径、主题、自动启用等
- `op_log`：文件操作事务日志（崩溃恢复对账用）

## 6. 错误处理

原则：**永不静默、永可恢复、永不丢数据**

- 文件操作先写 op_log 事务，中途崩溃下次启动自动对账修复
- 解压失败保留临时区，人话错误（"密码错误"而非 exit code），一键重试
- 游戏/路径/helper 提权问题各自独立非阻断提示，主功能永远可用
- SQLite 损坏 → 启动校验 → 从文件系统重建
- 滚动日志 + UI 内查看复制

## 7. UI 设计（液态玻璃）

**明暗双主题跟随系统**，共用一套玻璃配方：

- 玻璃材质：低着色（浅色 rgba(255,255,255,.28) / 深色 rgba(28,30,42,.38)）+ blur(28px) saturate(1.7~1.8)
- 发丝级高光：顶部 0.5px 亮边 + 微弱内折射环；0.5px 半透明描边
- 阴影去彩色化：柔和灰调双层投影分层，不用发光表达层级
- 大圆角：窗口 26 / 面板 20 / 卡片 18 / 按钮全圆角胶囊
- 强调色克制：系统蓝（浅色 #0A84FF / 深色 #409CFF），仅用于选中描边（2px）与关键操作
- 选中态 = 蓝色 2px 描边，不用霓虹发光
- 角色卡：立绘铺满 + 底部极轻渐隐 + 名字玻璃胶囊悬浮
- iOS 语言：大标题导航、搜索胶囊、iOS 开关、底部悬浮工具条
- 文字高对比实色（Apple HIG），玻璃上不用半透明文字
- 侧边栏选中：系统蓝 13~18% 淡填充 + 蓝字
